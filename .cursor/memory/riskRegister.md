# BrockDJ Risk Register

Last updated: 2026-07-11

## P0 Critical

| Risk | Affected files / classes | Technical explanation | Impact | Planned approach | Status |
|---|---|---|---|---|---|
| FX effect changes can race audio processing | `src/fx/FxManager.cpp`, `src/fx/FxProcessor.cpp`, `src/fx/FxProcessor.h`, `src/engine/audio/MixerDspSource.cpp`; `FxManager`, `FxProcessor`, `MixerDspSource` | UI calls can change effect type and prepare/reset effect state while the audio thread is processing the same processor state. Atomics cover the selected type/amount, but some per-effect state containers and prepare/reset paths are not proven single-writer/snapshot based. | Audio glitches, undefined behavior, occasional crashes during rapid FX switching. | Introduce an audio-thread-safe FX command/snapshot handoff. Prepare heavy state off the callback, then swap immutable/preallocated state at block boundaries. | open |
| Scratch cache miss can perform synchronous stream or decoder work in the audio callback | `src/engine/audio/ScratchResampler.cpp`, `src/engine/audio/ScratchDeckBridge.cpp`; `ScratchResampler`, `ScratchDeckBridge` | `ScratchResampler::ensureWindow()` can call `reloadWindowFromDisk()` or `reloadWindowFromStream()` from `processBlock()`. Recent priming reduces the first-block miss, but cache misses still have a synchronous fallback. | Dropouts during scratch, especially after jumps or slow scratches near window edges. | Move scratch window refill to a prepared/bounded cache owned outside the callback; audio thread should use ready windows only and fail soft to silence/interpolation on miss. | open |
| RubberBand reset/prewarm can run in the audio callback | `src/engine/audio/TimeStretchAudioSource.cpp`; `TimeStretchAudioSource` | `getNextAudioBlock()` services `m_resetPipelineRequested` and can call `resetRealtimePipeline(true)`, which calls `stretcher->reset()` and `prewarmStretcher()`. | Long callback stalls when keylock state or scratch bypass transitions reset the RubberBand pipeline. | Convert reset/prewarm into a non-realtime preparation step and publish a ready stretcher state or bypass until ready. | open |
| Filter coefficient generation may allocate or do heavy work in the audio callback | `src/engine/audio/MixerDspSource.cpp`; `MixerDspSource` | EQ/filter smoothing is rate-capped, but coefficient generation and DSP assignment still happen inside `getNextAudioBlock()`. JUCE coefficient creation/assignment is not documented here as allocation-free. | Callback spikes during EQ/filter automation. | Precompute coefficients or exchange small immutable coefficient snapshots from a control thread; prove no allocation with instrumentation. | open |
| Analysis lifetime can outlive `TrackData` ownership assumptions | `src/rendering/WaveformAnalyzer.cpp`, `src/domain/TrackData.h`, `src/domain/TrackData.cpp`, `src/engine/DjEngine_TransportLoad.cpp`; `WaveformAnalyzer`, `TrackData`, `DjEngine` | `WaveformAnalyzer::stopAnalysis()` only waits 150 ms. The analyzer stores raw `TrackData*` and reports progress/completion after work. Track loads also use detached threads with queued callbacks. | Use-after-free or stale queued notifications during rapid load/close. | Make analysis ownership explicit: cancellable worker owned by a joinable controller, guarded weak pointer for UI delivery, and deterministic shutdown joins. | open |
| POSIX signal handler calls Qt from signal context | `src/app/ApplicationBootstrap.cpp`; `requestGracefulTermination()` | The SIGINT/SIGTERM handler calls `QCoreApplication::instance()` and `QMetaObject::invokeMethod()`, which are not async-signal-safe. | Undefined behavior or deadlock on Ctrl+C/SIGTERM. | Replace handler with a self-pipe/eventfd or minimal atomic flag; notify Qt from a normal event notifier. | open |

## P1 Important

| Risk | Affected files / classes | Technical explanation | Impact | Planned approach | Status |
|---|---|---|---|---|---|
| SQLite `integrity_check` can be expensive and runs during startup/self-check paths | `src/library/LibraryDatabase.cpp`; `LibraryDatabase::isHealthyDatabaseFile()`, `performMirrorSelfCheck()` | Health checks use `PRAGMA integrity_check`; `open()` runs it on primary/backup and mirror self-check can trigger more checks on timers. | GUI/startup stalls on large libraries or slow disks. | Use cheap checks for routine paths, reserve full integrity checks for recovery/manual diagnostics, and move heavy checks off the GUI thread. | open |
| Backup thread is detached and cannot be joined on shutdown | `src/library/LibraryDatabase.cpp`; `LibraryDatabase::startDeferredBackupSync()` | Backup sync starts `std::thread(...).detach()` and posts back through `QPointer`. Shutdown cannot wait for or cancel the worker deterministically. | Shutdown races, late queued callbacks, backup state uncertainty. | Replace with owned worker/future and join/cancel in `shutdown()`. | open |
| Track-load worker threads are also detached | `src/engine/DjEngine_TransportLoad.cpp`; `DjEngine::loadTrack*` worker path | Track loading uses detached `std::thread` and queued UI callbacks. A generation guard exists, but lifetime/shutdown joining is not deterministic. | Late callbacks or resource churn during rapid loading/shutdown. | Move to an owned worker pool or `QThreadPool` with cancellation and shutdown drain. | open |
| Four decks use precise 4 ms control timers | `src/engine/DjEngine_Core.cpp`, `src/engine/DjEngine.h`; `DjEngine` timer setup and `onTimer()` | Each deck runs a high-frequency timer for transport, sync, VU, scratch control and notifications. | GUI/event-loop pressure and jitter under four-deck load. | Consolidate control ticks or move time-critical state to audio-thread/block-synchronous logic with throttled UI notifications. | open |
| `DjEngine` setters can emit unchanged-state signals | `src/engine/DjEngine_*.cpp`, `src/engine/DjEngine.h`; `DjEngine` | Some property setters/apply paths have guards, but not all signal-emitting setters are proven change-only. | QML churn, avoidable binding reevaluation, noisy controller feedback. | Audit setters and add idempotent guards without changing QML API. | open |
| Master bus has a fixed 4096-sample internal buffer cap | `src/engine/DjMasterBus.cpp`; `DjMasterBus::prepareToPlay()`, `getNextAudioBlock()` | `m_bufferCapacity` is fixed at 4096; larger callbacks increment overrun count and return silence. | Silence on devices or hosts that deliver larger blocks. | Size buffers to `max(samplesPerBlockExpected, safeMinimum)` and grow only outside the callback. | open |
| `TrackData` coalescing/progress state may not be fully thread-safe | `src/domain/TrackData.h`, `src/domain/TrackData.cpp`; `TrackData` | Many data fields use `QMutex`, but progress/coalesced signal timing uses timers and QObject delivery across analysis threads. This is a verified risk area, not a proven bug. | Lost progress updates, stale queued signals, or lifecycle races. | Define thread ownership, use queued delivery to the owner thread, and keep mutable analysis state behind one lock/snapshot. | open |
| Tests/CI do not cover realtime and small-buffer behavior enough | `tests/smoke/*`, `.github/workflows/cross-platform-build.yml`, `CMakeLists.txt` | Existing smoke tests cover basic DSP/utility behavior but not thread races, callback allocation, or 64/128-sample buffer stress. | Regressions can land unnoticed in realtime paths. | Add deterministic unit tests for policies and targeted integration tests/instrumentation for callback constraints. | open |
| Shutdown manually processes Qt events after `deleteLater()` | `src/app/ApplicationLifecycle.cpp`; shutdown path | The lifecycle code calls `deleteLater()` and then `QCoreApplication::processEvents()`, which can re-enter application code during teardown. | Reentrancy bugs and late object access. | Use explicit ownership teardown and avoid manual event pumping during shutdown. | open |
| Startup may depend on first QML rendering without a robust fallback | `src/app/ApplicationBootstrap.cpp`, `src/app/ApplicationLifecycle.cpp`, `src/qml/main.qml`; bootstrap/QML shell | Startup exposes objects before/around QML loading and waits on UI readiness indirectly. Fallback behavior for first-render failure is not documented as deterministic. | Partial startup, blank window, or initialized backend without usable UI. | Add explicit startup states, timeout/fallback logging, and tests for QML load failure. | open |

## P2 Architecture And Maintainability

| Risk | Affected files / classes | Technical explanation | Impact | Planned approach | Status |
|---|---|---|---|---|---|
| `DjEngine` is a distributed god class | `src/engine/DjEngine.h`, `src/engine/DjEngine_*.cpp`; `DjEngine` | Transport, sync, cue, loop, scratch, track-load, settings and audio graph state live behind one large QObject API. | Changes have broad blast radius and hidden ownership coupling. | Split by ownership boundary over multiple small, behavior-preserving steps after critical races are fixed. | open |
| `DjEngine.h` is very large | `src/engine/DjEngine.h`; `DjEngine` | Header is about 746 lines and exposes many unrelated responsibilities. | Slow comprehension and risky edits. | Move private state and helpers into focused components/pimpl-style units while preserving QML API. | open |
| Many `DjEngine_*.cpp` files implement the same class and shared state | `src/engine/DjEngine_*.cpp`; `DjEngine` | Around 16 implementation files mutate the same object fields. | Invariants are hard to enforce and test. | Introduce real subcomponents with narrow interfaces and explicit ownership. | open |
| Global audio-device configuration lives near per-deck engine code | `src/engine/DjEngine_Settings.cpp`, `src/engine/audio/AudioDeviceUtils.cpp`, `src/engine/DjMasterBus.cpp`; `DjEngine`, `DjMasterBus` | Device manager/routing behavior is partly coordinated through deck-facing classes. | Device changes can affect deck code paths unexpectedly. | Centralize device/routing state in an application audio service. | open |
| Cue, loop, sync, transport, track-load and graph state need owned components | `src/engine/DjEngine_*.cpp`, `src/engine/audio/*`, `src/engine/scratch/*` | Some scratch logic is already componentized, but most deck behavior still shares `DjEngine` state directly. | Hard to reason about threading and event ordering. | Extract one domain at a time after the P0 realtime fixes. | open |
| Thread ownership and realtime rules were not documented | `.cursor/memory/realtimeRules.md`; audio/analysis/library subsystems | Before this task, rules existed only implicitly in code comments and prior memory notes. | New changes can accidentally add blocking callback work. | Maintain `.cursor/memory/realtimeRules.md` and require callback changes to cite it. | in Arbeit |
| Build/package version values were inconsistent | `CMakeLists.txt`, `.github/workflows/cross-platform-build.yml`; CMake project, CI packaging | CMake used `0.0.1` while CI exported `APP_VERSION=1.0.0`. | Artifacts and app metadata could disagree with the build. | CI now reads `CMAKE_PROJECT_VERSION` from the configured build and exports `APP_VERSION` from that value. | erledigt |
| Release builds used target-native architecture flags by default | `CMakeLists.txt`, `README.md`; build configuration | Linux release builds previously defaulted to `-march=native`; Intel macOS was intended by option defaults. | Published binaries could fail on older CPUs. | Native arch is now opt-in via `BROCKDJ_ENABLE_NATIVE_ARCH=ON`; default is portable. | erledigt |
| `TrackData.cpp` was listed twice in CMake sources | `CMakeLists.txt`; target source list | Duplicate source entry increased build confusion and could cause generator-specific churn. | Build hygiene issue, possible duplicate compilation warnings in some tooling. | Duplicate entry removed. | erledigt |
