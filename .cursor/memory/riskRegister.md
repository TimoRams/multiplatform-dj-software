## POSIX signal ownership audit (2026-07-12)

- Registration previously occurred in `ApplicationBootstrap.cpp` immediately after constructing `QGuiApplication`; both SIGINT and SIGTERM used `std::signal`. The handler directly called two non-async-signal-safe Qt APIs. The normal path is `QCoreApplication::quit()` → return from `app.exec()` → `ApplicationLifecycle::shutdownApplication()`, whose teardown phases are additionally guarded by `once_flag`.
- `PosixSignalHandler` now owns both pipe descriptors and the `QSocketNotifier`. Initialization sets `O_NONBLOCK` and `FD_CLOEXEC`, installs handlers with `sigaction`, and reports setup errors from normal startup context. A failed integration is logged and the application continues without custom POSIX handling.
- SIGINT/SIGTERM only write one byte. EAGAIN/full pipe is intentionally ignored because an earlier byte already represents the shutdown request. The notifier drains through EAGAIN, disables itself, and emits exactly once; later signals cannot start another Qt teardown and do not force `_exit()`.
- Destruction blocks the two signals briefly in the owning thread, restores the prior actions, clears the trivial global descriptor, disables/destroys the notifier, closes both descriptors, then restores the signal mask. No complex C++ object pointer is visible to the signal handler.
- Active on Qt Unix platforms, including Linux and macOS. Windows neither constructs the component nor builds the POSIX test; the source remains compilable without POSIX includes. Windows shutdown behavior is unchanged. macOS/Windows runtime testing remains CI or platform-hardware work.

## Analysis ownership audit (2026-07-12)

- Deck: `DjEngine` owns one persistent `TrackData` child and one `unique_ptr<WaveformAnalyzer>`; the analyzer borrows both `TrackData*` and the deck-owned format manager. Track replacement joins before `TrackData` is cleared/reused. Same-track reload gets a new analyzer generation.
- Library: `LibraryAnalysisManager` owns the queue, one `TrackData`, one analyzer and its format manager. It processes one job at a time; the queue is now a `deque`. Cancel invalidates the manager job generation, requests worker cancel, joins, then destroys job objects.
- Worker start/cancel: JUCE `startThread(background)` runs `run()`. `requestCancel()` is non-blocking and invalidates generation; `shutdownAndJoin()` signals and waits without timeout. Existing envelope/feature/key loops check cancellation by chunk; checks also exist between envelope, rhythm, key and persistence phases. A third-party key-analysis call cannot be interrupted inside the library call (verified bounded to the first 90 seconds), so shutdown may wait for that call; detach is deliberately not used.
- Result delivery: waveform, BPM, grid, segments and key are calculated on the worker and written through mutex-protected `TrackData` methods; UI signals are Qt auto/queued delivery. Completion is an immutable `{completed,generation,filePath}` value. The manager validates `QPointer`, its monotonic job generation, analyzer generation and exact file path before DB publication.
- Thread fields: waveform/metadata/beatgrid/segments are under `m_mutex`; progress and active are atomic; `m_lastEmittedProgressPct` is atomic. `m_rgbEmitPending` and `m_rgbEmitClock` are owner-thread-only after queued scheduling. Audio/render consumers obtain copies/slices under the mutex. No concurrent analyzers target one `TrackData` because every restart joins first.
- Shutdown order: reject/invalidate current work, clear callback, request cancel, join worker, discard queued stale completions by generation/QPointer, then destroy manager/deck dependencies. Deck track loading now follows the same joined-lifetime rule.
